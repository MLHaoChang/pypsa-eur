# Gate S8: frontend, the guided flow (b6566fa assessed against 5791dce)

**Verdict: GO WITH BINDING CONDITIONS**

The guided flow is well built. The suites are green, and most of the carries are really done: the HELP mirror has a genuine both-way parity test, only the status routes are polled, the Expert view targets the fork, and auth mode and the disabled flag degrade gracefully. The upload parser refuses every malformed file I gave it.

Five defects remain on the novice's path. Each is cheap to fix, and each puts an untrue or unread statement on screen:

- The headline sentence is garbled: "0.3 MW MW with 1 h hours".
- A `bess_pv` verdict hides the battery-only answer and the total NPV.
- The by-construction note sits below the numbers it qualifies, and nothing explains what NPV means.
- The "Check your answers" page in edit mode shows values that were never saved.
- "None of your existing projects is changed" is false once a load file is uploaded.

A sixth defect is in the parser: a header naming W, GW or kVA is silently overridden by the intake's unit.

Two refresh paths are also untested: the refresh after a re-run or a tornado survives mutation. The binding conditions are BC-S8-1 to BC-S8-7 below. Satisfy them in S8 and re-verify; no full re-gate is needed.

### 3. Backend changes

- **[B5] A header naming a unit other than kW/MW is silently overridden by the intake's unit** (binding, BC-S8-6).
  - `_HEADER_UNIT_RE` recognises only `[km]wh?`. Anything else (W, GW, kVA, and case-folded mW) counts as "no unit named", and `load.unit` wins.
  - What was checked:
    - `load (GW)` with MW chosen: accepted, peak 0.0015 MW (1000× low);
    - `load (W)` with MW chosen: accepted, 1500 MW (10⁶× high);
    - `load kVA` with MW chosen: accepted.
  - The low case raises no warning: `peak_exceeds_connection` catches only the high one. Its likely outcome is a zero-size battery and a "Not recommended" verdict from a file the user thought was checked.

- **Everything else in `parse_load_upload` is refused with a typed code and a sentence a user can act on.** What was checked:
  - 8784 rows (both leap-dated and running into 2026);
  - a DST gap and repeat in local wall-clock time;
  - ISO timestamps with +01/+02 offsets;
  - two rows swapped;
  - a kW header against an MW answer;
  - negative, NaN, empty and `=1+2` cells;
  - `dd.mm.yyyy` (refused at row 25 with the date it read), and a file from 2023;
  - 15-minute data (35,040 rows);
  - semicolon files with a decimal comma.
  - A formula in the header is ignored and never stored.
  - The largest file I tried, 18.9 MB with 900k rows, is refused in 3.6 s; uploads are capped at 25 MB.
  - Note: a correct local-time meter export is always refused, because of DST. That is safe, but novice-hostile. Offer "timestamps ignored, read in order" as the documented fallback in the copy.

- **`timeseries_qa.check_series`: purely additive.**
  - The diff only appends a function. It reuses `_check_column` and `_PROFILE_TARGETS`, and returns nothing for an unknown kind.
  - `test_timeseries_qa` passes. `_check_load_scale` is deliberately network-only.
  - QA findings reach the page as `load_upload_qa_<code>` plus the QA module's own sentence (all-zero and flat probed).
  - The QA negative check can never fire, because negative values are refused first. Harmless.

- **GET `/library` and POST `/preview`: correct.**
  - Access: `ProjectAccessDep` gives 404 on an unknown project, and each handler repeats `_refuse_unless_enabled()`.
  - Route order: both are declared before `/{study_id}`.
  - Solver gate: exempt through the study-routes pattern, which is correct because neither route touches a network.
  - `/preview` builds no network, solves nothing and writes nothing. It reads the path project's upload through `upload_service`, whose `file_id` allowlist refuses traversal. A lock or in-flight check is correctly unnecessary for a pure read.
  - Of 13 malformed intakes, every one answers 200 with a typed `not_established`; there are no 500s.
  - Nit: a negative or non-numeric `connection_mw` previews as `ok`. Creation refuses it.
  - Golden coverage registers both routes with `frozenset()` and a reason.

- **`value_streams_basis`: correct.**
  - It is typed `Literal["baseline","pv_only_reference"] | None` on `Findings`, and set only when the streams are `ok`.
  - It is asserted in `test_study_tornado_routes` for both the baseline case and the PV-before-reference case.
  - The frontend falls back to the note for older payloads.

- **Two refusal codes lack `ERROR_COPY`** ([N2]): `load_profile_invalid` and `import_link_inactive`. They are packs codes, reachable only through `/preview` or creation.
