## 1. Contracts (`models/study.py`) against spec §4

**Checked:**
- Every listed model is present, and each has a round-trip test in `tests/test_study_models.py` that keeps its nulls: `DecisionStudy`, `DecisionQuestion`, `LedgerRow`, `AssumptionsLedger`, `DemandCharge`, `Tariff`, `OptionSpec`, `OptionResult`, `InvestmentCase`, `Findings`, `DecisionReport` and `StudyMaturity`.
- The enums `Perspective`, `Basis`, `VerdictClass` and `Fidelity` carry the spec's names.
- `SectionState` and `SectionStatus` are imported from `models/energy_hub.py`, not redefined. `test_section_types_are_the_energy_hub_ones_not_copies` pins identity with `is`. `ReportSection` subclasses `SectionState`.
- `currency_year` is present on `LedgerRow`, `Tariff`, `DecisionStudy`, `OptionResult`, `InvestmentCase`, `Figure` and `DecisionReport` (review v1 N10).
- Nullable figures derive from `_FigureBlock`. Its validator `_null_carries_a_flag` refuses three things: a null without a reason, a reason beside a value, and a reason that names a field which is not a figure. `Figure` enforces the same rule with a scalar reason. A real `0.0` needs no flag (`test_a_real_zero_stays_zero`).
- Completeness `status` exists per section: `Verdict`, `Robustness`, `InvestmentCase` and `StudyMaturity` each carry a `SectionStatus`. `Findings` and `DecisionReport` derive their completeness from their sections and refuse disagreement (`_completeness_agrees`).

**[SB-1 / S] Later phases cannot fill some fields as typed.** Every model has `extra="forbid"`, but the module docstring says later phases "FILL these ... they do not renegotiate the names". The plan already names fields that do not exist:
- **S5** needs `kpis.salvage_eur` and `salvage_basis=annuity_pv`, and wants the salvage "reported in `years[-1]`". `CaseKpis` has no `salvage_eur`, nothing carries a salvage basis, and `CashFlowYear` has no salvage column.
- **S4 and S6** each set a section `not_established` "naming the rest":
  - S4: "`completeness.options = not_established` naming the rest".
  - S6: "`tornado.status=not_established` naming the rest".
  - `Findings.completeness` is `dict[str, SectionStatus]` and `Robustness` has no note or pending list, so there is no typed home for the names. They would have to be pushed into `honesty_notes` prose.
- **S7** sets `report.stale` when the ledger hash or an option fork's network hash differs from the hashes "recorded at findings time". `DecisionReport` has no `stale` or `stale_reasons` field, and `Findings` has nowhere to record those hashes.
- The S5 XLSX Provenance sheet also wants model and ledger hashes.

**[S] Provenance on `Figure` is optional and unflagged.** The global constraint puts `basis`, `currency_year`, `engine` and `fidelity` on every figure. `Figure.basis`, `currency_year` and `fidelity` default to `None` with no flag, so a money figure (unit `EUR`) with no basis or currency year validates. Two fixes are available:
- Add a validator that requires `basis` and `currency_year` when the unit is a currency, and `fidelity` unless `engine == "ledger"`.
- Or make S6 and S7 check this at their gates.

`ValueStream` carries `basis` but no `currency_year`. It inherits the year from its enclosing `InvestmentCase`, which is acceptable, but the pattern is inconsistent with `OptionResult`.

**[S] ADR-0003 spelling.** ADR-0003 ("no generic `Resolved[T]` wrapper") ends: "when a new results surface is added, give it `available: bool` spelled exactly that way". The study contracts use two new spellings: `unavailable: dict[str, str]` on blocks and `unavailable: str | None` on `Figure`. A per-field reason map is defensible, since it is richer than a boolean and scope-qualified. But it has the inverse polarity and is a second spelling inside one module, which is exactly the drift ADR-0003 names as its reopening trigger. Two requirements:
- Record the choice in the module docstring (why a reason map, and why it is not a `Resolved[T]` wrapper), citing ADR-0003.
- Make sure every route that serves a whole surface (S5 `case`, S6 `findings`) still carries a payload-level `available: bool` where the whole surface can be unresolved.

**[S] Tariff semantics S3 will have to invent (`Tariff`, `TimeRule`, `ExportCompensation`, `DemandCharge`).**
- **Band precedence is undefined.** The test fixture's `off-peak` band has `applies: {}` ("always"), which overlaps `peak`. So the contract implicitly relies on first-match-wins without saying so. Pin the rule, either first match wins or bands must partition the year, and have S3's `BillCalculator` enforce it.
- **Export compensation is unvalidated.** The spec gives `price_per_mwh | series_ref` as either/or, but the model accepts both or neither.
- **Demand-charge bases beyond MVP-1.** `DemandCharge.basis` accepts `annual_peak` and `ratchet`. MVP-1's honest scope is one monthly demand charge, so S3's `_wrap_with_demand_charge` must refuse the other two with a typed error, not solve them as billing-period peaks. Carry this to the S3 gate.

**[N] Invented beyond the spec** (most are fine; pin or source these):
- `StudyBudget.solves_max = 12` is an unsourced default number. Derive it from `campaign.estimate_solves` in S4, or state where it comes from.
- `Engine` adds `cash_flow_expander`, `ledger` and `lp`.
- `LedgerRange.source` is `assumed | source`. This matches S2's `range_source = assumed`; keep it.
- `TimeRule` structure, `DecisionStudy.intake`, `basis`, `currency_year`, `updated_at`, `schema_version` and `honesty_notes`.
- `InvestmentCase.status`, `engine` and `fidelity`.
- `Robustness.method` (spec §13).
- `OptionSpec.omitted_assets` (BC-1).

All are consistent with the plan. Nothing needs removing.

**[N] Other contract nits:**
- `ValueStream` has only `label`. S6 streams and question `value_streams` are keys (`demand_charge_reduction`, …), so add a `key`.
- `TornadoRow.low_value` and `high_value` have no unit. The energy-price row is a multiplier.
- `Tariff.honesty_notes` is a `list`; every other `honesty_notes` is a `tuple`.
- `CashFlowYear.savings` is a non-null `float` while both bills are nullable. That is fine for a build year, but S5 must mark a case `not_established` rather than zero-fill `savings` for an operating year with a null bill.
- `_completeness_agrees` lets a non-empty `completeness` omit a section.
- `STUDY_ID_RE` accepts any 32-character lowercase hex while the docstrings say uuid4.
- `option_projects: list[str]` does not say whether the entries are uuids or names. S4 names forks `<base>-opt-<id>`; store uuids, because names can be renamed.

## 2. Persistence (`services/study/store.py`, `routers/projects.py`)

**Checked:**
- The sidecar lives at `<project dir>/studies/<id>.json`. `save_study` writes it through `atomic_io.atomic_write_text`, and `test_save_goes_through_atomic_io` spies on that call.
- `_path` validates the id with `STUDY_ID_RE.fullmatch` before any path is built. `_read` refuses a file whose `study_id` disagrees with its filename.
- There is a 1 MB size cap, and an oversize save leaves the old file in place.
- `studies` is in `_BUNDLE_DIRS`, not in `_BUNDLE_FILES`. The sidecar walk test asserts both.
- The bundle test is real. It exercises `GET /api/projects/{name}/bundle` (zip contains `studies/<id>.json`) and then `POST /api/projects/import_bundle`, and the study loads back equal.
- The snapshot test is real. It exercises `POST .../snapshots` (the snapshot directory contains the sidecar) and then `POST .../snapshots/{id}/restore` (the deleted study returns and a post-snapshot study is dropped).
- The seed studies are written with the store directly rather than through the flag-gated route. That is acceptable.
- The fork-skip note for S4 is present in two places: the store module docstring, and the comment above `_copy_bundle_dirs` in `_create_scenario_db`.

**[SB-2 / S] The id-validation test is vacuous (shown by mutation).** `test_a_malformed_id_is_not_found_without_touching_disk` passes with the `STUDY_ID_RE` check removed from `_path`. It passes because every probed path is simply absent, so `is_file()` and `FileNotFoundError` produce `StudyNotFound` anyway.

The property the check protects is real. Without it, an in-process caller (S4 onward) that runs `delete_study(project_dir, "../metadata")` unlinks the project's `metadata.json`, and `"../solver_config"` and `"../user_ts"` work the same way. HTTP cannot reach this, because `{study_id}` cannot contain `/` after decoding.

**[S → S4, and the SB-4 text] `studies/` now travels everywhere `_copy_bundle_dirs` goes:**
- Save-As
- user-created scenarios (`_create_scenario_db`)
- snapshot create and restore
- bundle import. This one applies in auth mode too: a crafted zip's `studies/...` members are now extracted, although they stay inert while BC-6 refuses the routes.

A copied record keeps its `option_projects`, `findings_ref` and `report_ref`. `routers/studies.py::_load` rewrites only `base_project`.

Snapshot restore has two consequences:
- **Restoring to an older snapshot can revert a study to a version** that no longer lists forks that exist, which orphans them.
- **Restoring to a pre-study snapshot does not remove `studies/`.** `_copy_bundle_dirs` skips a source directory that is absent. So the docstring of `test_snapshot_restore_brings_a_study_directory_back` ("restore replaces the directory, it does not merge") holds only when the snapshot has the directory. This is the same behaviour as `uploads/`, so it is not a regression, but S4 and S7 staleness must account for it.

## 3. Routes (`routers/studies.py`, `main.py`)

**Checked:**
- **Mount.** The router is mounted at `/api/projects/{name}/studies` before `projects.router`, with `dependencies=_projects_router_guard`. OpenAPI shows exactly `GET`/`POST /{name}/studies/` and `GET`/`PATCH`/`DELETE /{name}/studies/{study_id}`.
- **Access.** Every handler (`list_studies`, `create_study`, `get_study`, `patch_study`, `delete_study`) takes `project: AuthorizedProject = ProjectAccessDep`.
  - The mount test reads the app's effective routes and asserts `require_file_access` is present. It also asserts the BC-6 dependency precedes `require_project_access`.
  - A non-member (other org) gets 404 on all five routes and the sidecar bytes are unchanged.
  - A real id addressed through a sibling project gets 404, and so do unknown and malformed ids.
- **Lock.** Writes call `_check_project_lock` with a target built from the **path** project's `AuthorizedProject.uuid`. This is check-only; a free project stays free, which is tested. A foreign lock gets 409 `project_locked`, which is tested.
- **Per-step PATCH.** `step` restricts `intake` to that step's key, merge is shallow per key, and earlier steps survive (tested).
- **Refusals.**
  - A basis or perspective outside MVP-1 gets 422.
  - Attempts to write `study_id` or `option_projects` get 422, because of `extra="forbid"`.
  - Nothing is stored in either case (tested).
- **Prefix lists untouched.** `_SOLVER_BLOCKING_PREFIXES` and `_FOREIGN_LOCK_GATE_PREFIXES` are unchanged, and `test_neither_prefix_list_names_the_study_routes` pins that.
- **Middleware diff.** The only change is replacing `path not in _SOLVER_BLOCKING_EXEMPT and not any(path.endswith(s) ...)` with `not _solver_blocking_exempt(path)`. That function evaluates the same exact-set and suffix tests and then the new anchored regex, still on the raw `path`, as before.
  - For any path the regex does not match, gate behaviour is byte-identical.
  - The shutdown gate, CSRF, auth and the foreign-lock gate are untouched and still apply to study writes.
  - The undo and dispatch-invalidation prefixes do not include `/api/projects/`.
- **Exemption coverage.** I substituted every templated app route into the pattern. It matches only the five study operations; no other router has a `/{name}/studies` path, and there are no `:path` converters under `/api/projects`.
  - A percent-encoded `/` in the name segment is decoded before both matching and routing, so the pattern and the router see the same path.
  - A `..` segment is not normalised server-side, and no route matches it.
  - Conclusion: **there is no way today for the exemption to cover a network-mutating route.**

**[S → S4, S6, S7 gates] The exemption is forward-looking.** Every route S4, S6 and S7 add under `studies/` inherits the exemption automatically: `run`, `run/abort`, `findings/tornado` and `report`. The comment in `main.py` says so. At each of those gates, the assessor must check that every network-touching study handler carries its own context-parameterised check (`_refuse_if_mesh_busy`, or `_solver_in_flight_ctx(base_ctx)` per BC-5), with a test.

**[S → S4]** S1's `POST` attaches a record to whatever project the path names, including an existing user project. The docstring states this, and S4's "custom question" path does the same. S4 must make sure such a record can never be `run` with a pack against that project: question-first goes through M0 only. Otherwise the S4 M0 invariant ("every pre-existing project's directory hash unchanged") breaks. The S4 test must cover a study created on an existing project.

**[N]**
- The lock test cannot tell the path project from the active project, because they are the same project in the fixture. The code clearly uses the path project; a test where the active project differs would pin it.
- `DELETE` on an unreadable sidecar returns 500, so a corrupt record cannot be removed through the API.
- There is no `response_model`, so OpenAPI has no schema for S8 to mirror.
- `_WRITE_LOCK` serialises load, modify and save, but no concurrency test covers it.
