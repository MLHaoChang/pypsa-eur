## 3. BINDING conditions

1. **A8 scope.** Add `import_project_bundle` to the fix (evidence: chat tool `chat_tools.py:2354–2371` calls `import_bundle`, which binds at `projects.py:1059` and persists at `:1068` / `:1139`); correct the plan's pointer from `:1475` to those lines. Also check `save_project` from an unbound draft: `_save_context` binds (`projects.py:1929`) and `save_project` moves the pointer when `was_unbound` (`:1500–1502`) yet `save_project` is not in the set either — decide in the plan whether it needs the frame (the FE handler already covers "unbound → open").
2. **A1 lock mechanics.** `preserve_bus_topology` and `freeze_capacities` must acquire the lock the runner **passed in** — `preserve_bus_topology(n, lock)` / `freeze_capacities(n, lock)` with the five call sites (`sweep.py:400–401`, `frontier.py:211`, `coupling_loop_runner.py:625`, `margin_loop_runner.py:962`, `dtc.py:396` on a copy, no lock) updated — not `PyPSAService.get_lock()` resolved inside the worker thread. Reason: the runners capture `lock` at request time precisely because the worker runs under a copied context (`fmea_sweep_runner.py:56`, `coupling_loop_runner.py:285`, `margin_loop_runner.py:208`, `frontier_loop_runner.py:72`, `eh_study_runner.py:296`). The lock is an `RLock` (`pypsa_service.py:632`) and is not held when the `finally` runs, so no deadlock. Test (a) spies on the passed lock object.
3. **A1 refusal chokepoint and scope.** The plan says "`network_crud.py` or the route edge". It must be **both an HTTP and a chat-tool cover**: chat tools call router handlers directly through `_route` (`chat_tools.py:2115–2147`) and never pass `main.py`'s middleware, so a middleware-only guard leaves the assistant's `update_component` / bulk / undo unguarded during a study, while a `network_crud`-only guard leaves profiles, time-axis, cluster, vintage and undo routes open. Concretely: (i) extend the existing `solver_in_flight` branch (`main.py:769–800`, prefixes `_SOLVER_BLOCKING_PREFIXES`) with `running_study_key(ctx.solver_state)` restricted to the live-network studies and the existing `study_in_flight` shape; (ii) the same check in `network_crud` create/update/delete and in `undo_service` for the chat path. The plan must **name which `STUDY_KEYS`** (`project_context.py:256`) count as live-network (`fmea_sweep`, `frontier`, `coupling_loop`, `margin_loop`; `mc` and `eh_study` need one line of evidence each — the close-out says the EH study solves a copy, and refusing tagging edits during a 30-solve EH study would block the Guided Site card for no integrity reason). `/api/network/undo` must be included (it replaces the network in place, the exact swap-under-a-study hazard `study_swap_refusal` describes).
4. **A2 design.** (a) While the tab's project differs from the backend's bound project, every edit from that tab lands in the **other** project's live network — the hazard is edits, not only autosave. Option (a) must therefore block writes from the tab (a blocking banner, or the same `study_in_flight`-style 409 shape from the client side) until the user reloads X or adopts Y; "autosave suspended" alone is not enough. (b) Drop `GET /api/projects/active`: `GET /{name}` (`projects.py:2476`) would swallow it unless declared earlier, and a project literally named `active` would shadow it. `GET /api/network/meta` already receives `PyPSAService.get_loaded_project()` (`routers/network.py:601–604`, `_meta_payload`) and the recovery effect already calls it — add `bound_project` there (additive, no route-inventory row), and read it in `App.tsx:446–481`.
5. **P27 split.** P27 as written is two M items plus three S items across backend write behaviour, frontend recovery and smoke — L for one agent, and it mixes the only backend-write phase with FE work. Split: **P27a** (backend: A1, A8; gate row 2 adds `tests/test_chat*.py`, `test_chat_tool_dispatch_loop_seam.py`, `test_save_guards_seam.py`, `test_adequacy_study_swap_guard.py`, `test_adequacy_swap_guard_callsites.py`; smoke = P22.9 + edit-during-sweep + P25 chat-template-then-autosave) and **P27b** (frontend: A2, A5, A6; smoke = P22.9 restart step + P26 mid-study switch).
