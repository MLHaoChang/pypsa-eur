* Feat(pypsa-gui): One stored reliability goal per project. The solver config now holds the allowed shortfall (h/yr), the Monte-Carlo draws and the site type beside the energy-strictness (ENS) target, and the EH reference design, the coupling and margin loops, the sequential MC, the project readiness and the assistant's study tools all read it when a request leaves a field out: the stored value, then the project template's, then the study's default. Each run names where every goal value came from (`goal_sources`), and a value passed for one run wins for that run. `GET /api/projects/{name}/flow/reliability_goal` returns the resolved goal. Behaviour change: where a project's saved energy-strictness target and its template's disagree, the studies now use the saved one. Saving the shortfall, draws or site type does not mark a solve or an investment case stale; the ENS target still does, and two experiment cases that differ only in their goal stay comparable. An energy-strictness target of 0 still means "no target", so a template's ENS applies over a saved 0. `GET /api/projects/{name}` names goal values it ignores in `dropped_goal`, as bundle import does, and the assistant reads the goal with `get_reliability_goal`.
