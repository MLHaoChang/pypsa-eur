* Feat(pypsa-gui): Uploads accept GeoJSON (`application/geo+json`) and KML (`application/vnd.google-earth.kml+xml`), but only when the bytes parse the way the map-geometry import reads them. A file named or declared as GeoJSON/KML that doesn't parse never gets a geo type (it keeps its sniffed type, so a binary or XML one is refused), and so is a KML that isn't UTF-8 or declares a DOCTYPE or entity (the map import refuses those too, and parses with `defusedxml` when it is installed). Geo uploads are capped at the import's 8 MB.

* Fix(pypsa-gui): With the rolling-horizon strategy, `PUT /api/simulation/solver_config` (and so the chat's `update_solver_config` and its edit card) refuses an overlap that is not shorter than the window, a window under 1 or a negative overlap. It answers 422 `rolling_overlap_exceeds_horizon` / `rolling_horizon_invalid` / `rolling_overlap_invalid` with a message that says what to change. The check uses the same rule as the pre-flight check, and turning rolling off, or re-saving the form with an unchanged stored window, is never refused.
