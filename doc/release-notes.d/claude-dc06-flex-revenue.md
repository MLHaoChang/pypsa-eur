* Feat(pypsa-gui): The backup storage of a data-centre project (its battery strings, spares included, and its ride-through storage) can commit headroom to reserve products in generic FCR, aFRR and mFRR shapes. Each product carries a capacity price from a user Library series in the project's currency: a series in another currency is refused when the commercial config is saved, and flagged by the preflight if the finance currency changes later. No market prices ship with the app. A run whose reserve products cannot be built is refused before it starts, with the reason. The backup energy stays a floor the solve never commits: the sized string energy, or for a ride-through storage, the critical peak over the ride-through time. Capacity payments enter the investment case as a "Reserve capacity revenue" row. Activation energy, cycling wear and non-delivery penalties are not modelled. An optional reserve headroom on the backup spec buys extra string energy, priced once with the backup energy's depth of discharge, fade and augmentation. The Storage results view shows the floor and the committed bands, and the DC backup section links to it.
