* Feat(pypsa-gui): Project flow backbone. `GET /api/projects/{name}/flow` files the existing checks (the run preflight, the reliability study's own start refusals, the Energy Hub readiness, the project's bind issues, a template's assumed defaults and display-only presence rules) into the ten flow sections, from Project & site to Results, each `complete`, `warning`, `incomplete` or `not_needed`. `run_ready` is exactly the server's verdict, with the first blocker and the display-only `notes`; `POST …/flow/ack` acknowledges a warning until its value changes. The assistant reads it with `get_project_flow`, and workflow steps name their flow section. No UI yet.
