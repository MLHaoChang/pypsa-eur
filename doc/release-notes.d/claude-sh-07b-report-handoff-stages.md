* Feat(pypsa-gui): An `eh_site` harness run now has a report stage and a hand-off stage, and runs that were already in progress continue into both. The harness starts the report job itself. Its narrative sends are strict and charged to the run, and its harness chapter names every chapter or part of the request the run did not establish. The hand-off reads the headline KPIs back from their native results and records which parts of the request are covered. It also stores "Revert the run's changes" as one reviewed change preview, which the user applies on a card. A completed run's notice and email give the count of uncovered parts. A report the user starts while a run waits at its report stage is never strict and never charged to the run.
