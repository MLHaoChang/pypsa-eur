* Feat(pypsa-gui): A harness run whose solve is not optimal, or whose result gate fails, now runs the bounded fix-and-rerun loop L2 inside its approval envelope: the harness reads the triage first, the agent makes at most 2 size-cap changes a round (a third is refused as `round_change_cap`), each round is followed by one re-solve, and after at most 2 rounds the run stops and asks the user. Each round is a recorded cycle (the solve it judged, the findings, the changes, the next solve). The run's solve count (`run.budget.used.solves`) and the envelope's solve budget now read one counter, checked again where each solve is recorded; a solve whose captured result was not applied because the inputs changed stops the run `inputs_changed` and still counts as spent.
