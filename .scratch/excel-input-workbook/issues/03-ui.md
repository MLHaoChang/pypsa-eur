## Comments

S2 (issue 02), 2026-11-21: the routes S3 builds on.

- `GET /api/workbook/template`: the blank template. It reads no project.
- `GET /api/projects/{name}/workbook`: a project as last saved. Unsaved edits are not in it; say so beside the button.
- `POST /api/workbook/preview` (multipart `file`): returns `{sha256, suggested_name, summary, report, rederived, not_carried}` and writes nothing.
- `POST /api/workbook/import` (multipart `file`, `expected_sha256`, optional `name`): creates the project and does not open it. Call `POST /api/projects/{id}/activate` afterwards. A file that changed since the preview gets 409 `import_file_changed`.

`/api/io/import/excel` refuses the input workbook with 422 `import_as_new_project`, so the Import dialog should send it to the preview flow.

Route parity: when the UI binds these routes, declare the two GETs `binary-transfer` and the preview and import `held-by-spec` with issue 06 (S2 could not: `--check` refuses a declaration no GUI binding reaches).

Ask: an entry from Hand-off › Exports (download this project's workbook, the template, and import a workbook as a new project), and one from Guided's new-project start (start from a filled workbook). Chat follows in issue 06.
