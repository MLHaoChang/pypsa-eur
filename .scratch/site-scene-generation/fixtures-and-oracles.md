## Seam and evidence requirements

- Backend HTTP: actual authenticated client, native project registry/ACL/lock and real scene/media/result services; measure response, disk state and receipt. Fault injection may interrupt the filesystem operation but cannot replace persistence with a stub and certify crash safety.
- Frontend/component: fake transport can exercise display/error handling, but cross-stack browser tests must use real frozen API responses/services for availability, approval and resume claims. Capture Guided and Expert plus keyboard/reduced-motion cases.
- Native mathematics/topology: literal analytic expected values or a reviewed existing native oracle, independent from scene projection. Compare exact identities/units/signs/snapshots and unavailable reasons.
- Assistant: substitute provider decisions only. Drive ordinary dispatch, current policies, approvals and native handlers; assert forbidden calls did not occur. No paid calls. Conversational model quality remains separately authorized evaluation.
- External engines: fast tests may fake worker invocation for orchestration only. Record a separate genuine pinned Blender/photo run with inputs/output hashes and failures; a fake green worker never enables the capability.
- Performance: actual target packaged device and representative admitted scene size. Record method and sample distribution. No jsdom performance certification or guessed universal frame-rate promise.

The initial eight domain fixtures in validation-matrix.md must exercise the applicable native model/process/result adapters. F01–F08 are reusable building blocks, not substitutes for domain coverage. Keep each case's parameterized assertions and engine exclusions explicit in the evidence record.
