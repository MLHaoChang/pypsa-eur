# HH-06 — Durable native study and bounded correction cycles

Status: needs-triage
Type: detailed implementation specification; this commission changes documentation only
Baseline: `master` `60d8332d64b2edef1b204fb5980311e6102229a8`
Depends on: study-harness 01–05, 08; HH-01/02/03/04/05/09/10 integration prerequisites below; HH-08 report closure

## Outcome and ownership

The owner can parameterize an engineering study, approve its scope, leave it running on the server for hours, work elsewhere, and return to an inspectable sequence of inputs, native simulations, findings, proposed changes, approvals and reruns. The assistant explains the native findings and proposes bounded design changes. Native software decides applicability, validation, result status and gate outcomes. The process stops honestly when the approved question cannot be answered.

This is the reliability integration specification for existing study-harness issues [04](../../study-harness/issues/04-input-gate-agent-loop.md) and [05](../../study-harness/issues/05-result-gate-and-rerun-loop.md), not a second runner, optimization engine or correction service. Their existing L1/L2 limits and study-harness [design](../../study-harness/design.md) remain authoritative. HH-01 owns revision-atomic effects and `InputVersion`; HH-02 owns confirmed requirements; HH-03 owns `PreparedCall` and durable call accounting; HH-04 owns references; HH-05 owns independent trajectory qualification. [HH-09](09-coordinator-delegation.md) owns `IntentContractV1`/`DecisionPacketV1`, acceptance IDs and native-checker/human-review closure in `harness/decision_packets.py`; HH-02's narrow input predicates cannot stand in for all user acceptance criteria. [HH-08](08-report-workbook-revisions.md) reports the same acceptance IDs. This issue consumes those contracts without redefining them. Research is the separately approved optional module [HH-07](07-research-parameter-proposals.md).

Passing a finite plausibility rule set means the tested checks passed on the stated model and evidence. It does not establish scientific truth, validate assumptions against reality, prove global optimality, certify regulation or establish safety. A solver objective is the solver's recorded objective on its declared weighting and units; it is not automatically full lifetime cost or a physical quality score. Preserve those distinctions in the brief, progress and report.

## Concrete native fixed-dispatch facts and rule coverage

The proposed native extension **`services/results/capacity_checks.py`** owns `CAPACITY_CHECKERS_V1`, `eligible_fixed_dispatch(n, cfg)`, `observe_fixed_dispatch(input_n, output_n, cfg, observation_identity, policy)` and `read_fixed_dispatch(section, result_scope)`. These are native result functions, not harness/LLM calculations. Register the closed capability **`capacity_fixed_dispatch_v1`** on `capacity_isolated@1`; this capability is narrower than HH-10's immutable LOPF queue adapter. HH-06 setup must prove both before unattended submission. A wider HH-10-eligible network can use its separately authorized native solve, but it cannot enter this completed correction-cycle profile until another numerical checker capability is specified and qualified. Missing implementation is `unsupported`, not permission to stub a pass.

This extension supplies the three checks expressly deferred by K's first-five-rule scope: balance, dispatch bounds and the frozen economic target/basis. It neither reimplements nor renames K's `lost_load`, `branch_overload`, `curtailment_share`, `storage_simultaneous` or `build_at_bound`. Keep K observations/version/applicability separate. Component-absent checks may be recorded as not applicable only under the approved native applicability map; required applicable K observations that are missing/unavailable stop the gate. K's absence still blocks first-profile activation, as C04 requires. Assurance10 remains the sole checked-publication follow-up; these native facts do not expand strict `get_results` admission.

**Closed first numerical domain.** One electrical MW bus; 1–128 fixed, active, noncommittable Generators and 1–128 nonnegative Loads, all attached to that bus; 1–10,000 ordered flat snapshots. All other component classes with equations (Line, Transformer, Link, Store, StorageUnit, ShuntImpedance, GlobalConstraint and any future class) must be empty. Generator `sign=+1`, Load `sign=-1`, `p_nom_extendable=False`, finite `p_nom>=0`, finite scalar nonnegative `marginal_cost` with no time-varying override, `marginal_cost_quadratic=0`; no ramping, dispatch-fix `p_set`, commitment, capacity-cost, curtailment subsidy or extra objective terms. All active status/build/lifetime semantics must include the full horizon. Capital/FOM/overnight cost contributions must be exactly zero or native absent, with no composite/library cost derivation. Config is HH-10's complete pinned default inventory, additionally `voll=0` and `co2_price=0`; no native transformation may change demand, weights or marginal cost. Validate all remaining equation-bearing network attributes against a versioned native default/allowed-field inventory, including bounds and infinity sentinels: a new field/class or nondefault unsupported constraint refuses, never silently disappears. This also excludes targets that require lost-load slack, reliability, branch/storage physics, optimized expansion or full investment economics. No forced input gap is needed for this valid model.

Read exact immutable input through HH-10 verified hydration and the exact quiescent restored output generation, never global/router cached results. Resolve static-versus-series input precedence with native `n.get_switchable_as_dense("Load", "p_set")`, `n.get_switchable_as_dense("Generator", "p_min_pu")` and `n.get_switchable_as_dense("Generator", "p_max_pu")`. Require unique names, exact snapshot/column inventory and complete finite cells after native precedence resolution; `0<=p_min_pu<=p_max_pu<=1`. An explicit dynamic NaN, missing/duplicate snapshot or extra/unrecognized output row is unavailable, never filled with zero or silently reindexed away. Native static defaults are valid only when the native schema actually defines them. Read solved MW from **this output's** `generators_t.p` and `loads_t.p`, with exactly the admitted component inventory. Existing `results.load_frames.lp_scaled_load_frame(..., from_state=False)` confirms the private-output distinction, but its input fallback cannot establish successful output here. Native input demand and solved Load power must agree within the MW tolerance before economic evaluation.

Read both admitted `snapshot_weightings.generators` (energy) and `.objective` (cost) explicitly, including exact ordered index. Require each weight finite, strictly positive and expressed in the frozen declared hours basis, with **elementwise identical energy and objective weights** in this first capability. Use `services.period_utils.snapshot_weights` only after this strict check; its ordinary fallback-to-objective/1 behavior cannot qualify missing weights. These choices match `results/dispatch_digest.py` (energy uses generators), `results/physical_quantities.py` (energy versus cost weights) and the native `solver_service.run_simulation` full-horizon `network.optimize` path. No 8,760-hour annualization, sample-count divisor or period-years multiplier is added on a flat network. Unequal energy/cost weights require a later explicitly described target basis, not an automatic unit reinterpretation.

For snapshot `t`, admitted demand `D[t]=sum_l p_set[t,l] MW`, actual generation `G[t]=sum_g p[t,g] MW`, and common weights `w[t] h`. Compute per-cell bounds `L[t,g]=p_nom[g]*p_min_pu[t,g]`, `U[t,g]=p_nom[g]*p_max_pu[t,g]` in MW. Frozen checker-version tolerances are `tau_mw(x)=1e-6 MW + 1e-8*abs(x) MW` (when x is numerically expressed in MW), `tau_eur(C)=1e-4 EUR + 1e-8*abs(C) EUR`, and economic comparison `tau_rate=1e-6 EUR/MWh`. These are observation tolerances, not changed solver options or authority for the model to relax criteria. Count a balance violation where `abs(G[t]-D[t])>tau_mw(D[t])`, a solved-load mismatch using its admitted per-cell demand scale, and a generator bound violation if `p<L-tau_mw(L)` or `p>U+tau_mw(U)`. Check every cell/snapshot; horizon net cancellation cannot hide opposite per-snapshot residuals.

Compute **served-demand energy** `E=sum_t w[t]*D[t] MWh` only after input/output demand, balance and bounds checks pass; require `E>0`. Compute **variable generation cost** `C=sum_t,g w[t]*p[t,g]*marginal_cost[g] EUR` and `R=C/E EUR/MWh`. No generation-energy denominator, capacity denominator, rounded display values, backup share or solver-reported objective alone can replace them. Require all sums/ratios finite. For this closed zero-other-cost domain, compare native restored `network.objective` with `C` using `tau_eur(C)` and require native `network._objective_constant` zero; mismatch means unavailable basis, not a better economic outcome. This is a reconciliation check, never a general assertion that PyPSA objective equals lifetime cost. `solver_service.py` and `results/objective_decomposition.py` explicitly distinguish constants and fixed costs outside this domain.

## Deterministic cycle and terminal criteria

At intake freeze the user question, objective descriptors, horizon/weights, requirements, applicable profile/rule versions, thresholds, assumptions, tunables, bounds and existing budgets. Defaults come from the profile/envelope; no new user knobs. A user amendment creates a new reviewed policy revision and invalidates pending proposals. The model cannot relax a threshold, change a denominator, discard a scenario, reduce demand, modify fault levels, reclassify missing results, alter solver tolerances, mark assumptions verified or remove an adverse case to make the output look plausible.

Execute this state progression within the existing nine stages:

1. Resolve fresh ACL, project context, restrictions and HH-02 binding. Capture the native input observation and evaluate required inputs. Unknown blocking input facts stop. An optional warning remains visible.
2. L1 starts only on failed blocking input rules, with at most three rounds, lowered only by the existing profile. The model proposes named gap/design changes; native code validates tunability, complete candidate requirements and ordinary card/envelope policy. Each actual effect obtains HH-01 admission and verified receipt; a failed/missing receipt stops the round.
3. Submit exactly one admitted native solve using frozen input/job identity. Reserve its solve count before possible submission; all inner engine solves count. Wait without holding project, parent or card locks. Native settlement and immutable evidence must identify that exact attempt.
4. Evaluate native applicability, solve condition, freshness and registered result rules. Produce a bounded explanation from those findings. A non-optimal solve invokes existing triage reads before considering a correction. Missing/nonfinite/no-evidence is `not_evaluated`, never a zero or pass.
5. L2 starts only on failed blocking result rules or registered recoverable non-optimal solve. Limit to two rounds per case and two changes per round. Each round consumes a solve; no re-solve without a verified effective input change. Warnings alone cannot trigger an unapproved search for a nicer result. Native reliability loops replace, rather than nest within, the agent loop for their rule.
6. Before continuing, compare the canonical failing-rule set and native input fingerprint with prior rounds. Repetition is `no_progress`; returning to a prior input/failing-set pair is an oscillation and the same stop. A changed fingerprint alone is not proof of improvement. Preserve all failed findings.

Native gate completion requires every required blocking rule to pass on matching, complete evidence and every required stage to be complete or explicitly skipped by the approved profile. Call this “Completed checks” with assumptions/limits; assumed inputs yield a screening pass. `converged` is reserved for a native loop that reports its own registered convergence fact. No universal convergence epsilon or LLM confidence cutoff is introduced.

Terminal/wait reasons are structured: `completed`, `needs_user`, `no_progress`, `infeasible`, `unsupported`, `uncertain`, `budget`, `expired`, `paused`, `cancelled`, `failed`. Map them onto existing run statuses with a reason, rather than expanding the runner's status vocabulary unnecessarily. Native proven infeasibility is distinguished from “no feasible design found within these bounds.” Exhausted rounds do not prove global infeasibility. Unsupported readers/fidelity stop before effects. Uncertain submission, partial change or unavailable receipt blocks continuation and reconciliation is readback-only. The owner may approve a new scoped study, never reset spent counters by resuming the old one.

## Hours-long operation, concurrency and recovery

Retain server runner scheduling and task ownership; the browser observes. Closing the tab, switching projects, changing providers or using another card cannot advance or cancel the run. The owner can work on other projects immediately. Same-project edits use existing native locks; short critical sections may be busy, and external drift pauses the cycle before further effects. Do not freeze the entire interface for eight hours or switch the active project to a background context.

Existing envelope solve/round/wall-time limits apply across stages, cases, reconnects and worker takeovers. `eh_site` currently proposes six solves, six rounds and eight wall-clock hours; retain source hard caps. The first isolated-capacity lineage is narrower: HH-10's maximum three physical solves including the initial solve overrides any wider profile allowance. Wall time starts at the original approved run start, includes waits and pauses and never restarts on resume. New work may not start after the deadline. An already submitted native job is observed to its honest outcome; expiry cannot imply cancellation or refund. HH-03B qualification is mandatory for the exact operation manifest before any paid stage starts: study inference, review, research/retrieval fees and reachable report/repair/worker subcalls share its broker and parent/task/day ceilings. HH-03A main-chat/reviewer coverage alone is insufficient. Unknown capability returns `not_available` before planner spending; unknown sends retain holds. No model call occurs under native or parent locks. Use canonical lock order: mutation, solver-state if required, owner transaction, source-checked leaf locks.

Pause prevents new admissions, revokes live pending cards and preserves counters/history. Stop revokes the envelope and cancels continuation; already applied changes and submitted jobs remain recorded. Native cancellation occurs only through its supported explicit semantics. Resume rechecks actor/project, current inputs, profile availability, requirements, restrictions, unexpired grant and remaining budget. Changed policy or researched assumptions require fresh review. Never restore a serialized approval token.

Recovery obtains the existing lease/claim and folds durable action checkpoints. A live matching job is followed; an intact matching terminal receipt settles once. A positive pre-effect close checkpoint can establish no effect. Missing job ID, expired lease, process death or a returned error cannot establish no effect. Unknown native submission is `uncertain` and never automatically retried. Late results append once to the same action identity. Durable idempotency keys use cycle/stage/round/action/attempt, with payload digest conflicts refused. Lease takeover alone never creates a second effect.
