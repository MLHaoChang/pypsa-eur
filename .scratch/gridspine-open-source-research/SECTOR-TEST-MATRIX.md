# Sector integration acceptance matrix

Status: proposed tests and reference requirements; **none of these new adapter/integration tests were executed by this research**. Existing native test results are not re-certified here.

## Common gates for every adapter and example

| ID | Cases / assertions | Reference and admission rule |
| --- | --- | --- |
| X01 Units/bases | MW/MWh, kW/kWh, kg/t, LHV/HHV, currency and year, real/nominal, timezones and interval durations; reject incompatible/missing basis | Hand-derived dimensional fixture; explicit conversion round-trip. Never infer basis from a display label alone |
| X02 Chronology | Reordered/duplicate/missing timestamps, DST, leap input, nonuniform weights, 8,760 nominal vs actual calendar; multi-period boundaries and inventory | Known energy/peak/inventory fixture; documented mapping or named refusal; never silent truncation |
| X03 Validity | Out-of-range inputs, wrong chemistry/equipment, NaN/inf, negative capacities, extrapolation and insufficient calibration | Adapter-specific bounds; refuse unsupported values before producing a valid envelope |
| X04 Conservation | All material/energy ports, losses, inventories and delivery reconcile; no free auxiliary/by-product | Independently hand-summed cases and selected external reference; sign/unit conventions explicit |
| X05 Ownership/freshness | Wrong owner/project/revision, changed parameter-library pin, stale operating point, mismatched engine/image/schema | Must refuse applying/claiming fresh evidence; existing receipts and source hashes bind exact inputs |
| X06 Job safety | Denial, timeout, cancelled/partial/infeasible run, worker crash, exhausted budget, duplicate retry | No unauthorized effect or invented success; native cleanup/reservation policy and idempotent receipts hold |
| X07 Artifact integrity | Truncated/corrupt series, changed checksum, wrong asset/window, synthetic substitute for missing evidence | Unavailable/unchecked under current contract; no checked publication from corrupt or foreign artifacts |
| X08 Assurance | Wrong number/sign/unit/entity/window, extra unsupported claim, missing oracle, unsupported multi-period/product scope | Registry disposition for each metric; model prose never certifies output; deterministic receipt reconstruction |
| X09 UI parity | Guided/Expert/library/assistant refer to same fields; single/staged choice; supported subsets; Select all applicable | Browser tests on real components, including keyboard/touch; no shadow model or hidden mutation |
| X10 Boundaries | Electrical screen vs dynamic proof; measured vs fitted/synthetic; forecast vs historic; partial bill vs total; green intent vs certificate | Labels/withholding match source and claim disposition; native freshness distinct from copilot verification |
| X11 Isolation | Pin incompatible stacks separately; no runtime package fetching; default worker no network; bounded files/resources | Reproducible worker build, package/license manifest, resource/cancel test and staged-data-only execution |
| X12 Regression | Existing native example without optional module remains identical on declared invariants | Compare capacities/dispatch/objective under solver tolerances; explain any numerical/version drift |
| X13 Five-card composition | All32 top-level selections on fixture contexts: complete fixed model, saved native run, incomplete project, unavailable worker and restricted user | Supported plan or exact per-feature refusal; empty selection remains editable draft/no execution; no hidden prerequisite card/job |
| X14 Feature composition | Pairwise admitted feature interactions plus lifecycle+reliability+finance, H2+NH3+inventories, grid-trip+process-restart+lost production, IPP price+contracts+storage | Inputs/providers/units/constraints shared once; unresolved active requirements refuse; no additive double-count or irrelevant card dependency |
| X15 Add/remove/re-add | Individual subfeature/card, dependent removal/rebinding, selected/unavailable state, disabled constraints and retained pins | Reviewed atomic diff; no silent cascade/purge; physical costs/limits/hard goals remain until explicitly changed; restored configuration revalidates |
| X16 Concurrency and migrations | Stale preview/registry digest, in-flight job completion, duplicate apply; old three/five-group projects, unknown/retired plugin and import schema | Immutable run manifests; old result cannot overwrite new active state; unknown selections retained unavailable; Hand-off not mapped to Reliability; rollback and explicit maps |
| X17 Backend admission | Direct API attempts to forge availability, features, workers, provider refs, cross-tenant artifacts and disabled-card execution | Same server-side permissions/approval/dependency checks as UI; no arbitrary code/image/import; no authority from registry labels |
| X18 Per-adapter execution | Each shipped component/version/platform through actual pinned worker and native round-trip, including missing dependency and corrupt output | Real numerical reference plus adverse fixtures; skipped optional tests cannot admit that capability; every enabled family gets actual E2E |
| X19 Private data | Meter/process input staging, logs, caches, library promotion and exact evidence downloads across tenants/projects | Least-necessary staged data, correct ACL/retention and dataset rights; no public shared cache or cross-owner output access |
| X20 Reliability basis | Method/annualization, weather ensemble, dependence/common-cause assumptions, seed/sample/stopping/CI, unavailable sample evidence | Known analytical case and reproducible stochastic reference; enough samples retained for checked reconstruction; unsupported CI/method explicitly unavailable |
| X21 Ageing time | Calendar ageing, repeated duty across investment periods, representative weights, replacement reset/partial replacement | Physical elapsed time stated; optimization weights alone refused; replaced cells do not inherit predecessor age; no energy-to-power inference |

Numerical thresholds are metric-specific. Use existing approved native tolerances where applicable; otherwise define a justified absolute + relative bound before implementation, record it in the fixture and review it. Do not claim a universal percentage proves all engines agree. Fit errors, dynamics convergence and approximate screens need separate acceptance criteria from exact accounting.

## End-to-end workflow coverage

For each admitted family, browser/API tests must exercise: example selection → planning period/investment dates → relevant controls → Advanced/Expert → preview changes → run → native results → copilot explanation → evidence/export. Add cancel/denial/stale-run variants. Validate enabled operations only; unavailable advanced studies must have a truthful visible reason.

Every shipped adapter/component/version/supported platform must use actual pinned-worker execution, a numerical reference and native round-trip in its claimed scope, including downloaded exact evidence bytes where applicable. Every newly admitted family workflow must exercise its real enabled paths; mocked UI/contract tests or one global worker journey cannot certify the rest. Optional skips keep that capability unavailable until evidence passes. Local tests, remote CI, numerical references and domain review are separate. Live paid-model tests stay opt-in, capped and manual.

Before a capability is called customer-validated, require an appropriate real-use dataset and independent domain review. Both remain pending by the owner's earlier choice; this design neither contacts reviewers nor claims their approval.
