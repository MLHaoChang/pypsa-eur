## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Undo one op of a refined series, not only the whole apply.

**Current behavior:**
A refined artifact records its ordered op list (`refinements`) and `based_on`, the artifact it was refined from. The refine route (`POST /projects/{name}/profiles/refine`) and the `refine_generated_profile` chat tool only append ops. Undo is the apply's whole snapshot. The change log names a refinement, but not its op parameters.

**Desired behavior:**
- Undoing op *k* of a refined artifact re-refines its `based_on` artifact with the recorded op list minus op *k*. The ops after *k* replay in order through the existing replay path, keeping their recorded resolved values (`resolved_mw`, `connection`). The result is a new pending artifact with its old→new card. Nothing is applied until the user accepts the card, as with any refinement.
- If removing op *k* makes a later op invalid, the undo is refused with a reason that names that op and its index (the same `InvalidRefineOpError`/replay refusal wording). It is never silently dropped.
- The undo is offered on the refined series, in the editor's refinement list (one "Undo" per op), and to the copilot as a tool argument (an op index on the refine tool, or a sibling tool), with the same old→new card.
- The change log entry for an applied refinement lists each op with its parameters, e.g. "scale_window ×1.2, Mon–Fri 08:00–18:00", not only the op name.

**Key interfaces:**
- The refine request gains a way to name the op to remove (e.g. `undo_index: int`), validated against the artifact's recorded op list.
- `profile_gen.refine`'s replay entry point is reused. Do not add a second op interpreter.

**Acceptance criteria:**
- [ ] On a series refined by two ops, undoing the second returns a card whose "new" equals the series after the first op alone, and accepting it applies that series.
- [ ] Undoing the first of two ops returns the series with only the second op replayed on `based_on`.
- [ ] An undo that leaves a later op invalid is refused, naming that op and its index.
- [ ] An index out of range, or an artifact with no refinements, is refused with a plain reason.
- [ ] The applied change-log line lists each op with its parameters.
- [ ] Backend tests cover the three cases above. A frontend test covers the per-op Undo control.

**Out of scope:**
- Replay on regeneration (issue 06).
- New op kinds (issue 07).
- Redo.
