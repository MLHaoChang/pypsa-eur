# Library-worthy GridSpine parameter inventory

Review date: 2026-10-20 (Europe/Berlin). Native baseline: `46035b4d853df2db8500d2fc1784da02d38bf539`. **80 parameter families**, grouped for source discovery; these IDs are research identifiers, not implemented feature or library-kind IDs. Source-only inspection, no application edits or model tests.

The prior baseline was `90c7b8ffcec104397383361212da0aa21f545f1b`; the delta to this baseline is docs-only (workspace modular-card/checklist/coordinator work). Application parameter mappings below are unchanged.

## What already exists

- `services/library/items.py` currently permits **tariff, contract, connection_agreement**. `series_store.py` separately stores versioned/org-scoped time series in the same library infrastructure. Do not build a second database.
- Versioned defaults packs already carry sourced technology-data costs/efficiencies/lifetimes, finance presets, tariffs and synthetic load CSVs. The unified library design expands kinds; most requested family kinds below are proposed extensions, not existing APIs.
- `attribute_catalog.py` reads the pinned PyPSA defaults metadata for generic component attributes. A full-field import must use this allowlist plus native validation; library data cannot create arbitrary model fields.
- `campus_assets.yaml` explicitly marks **all** shipped campus electrical prices, ratings and impedances unverified/assumed. Replacing these with source-backed entries has high value, but public generic figures are not a vendor quote.
- `occurrence.py` already resolves per-asset `outage_rate_value`, `outage_rate_basis`, `mttr_hours`, then approximate carrier defaults. FOR and EFORd are never silently converted. Missing carriers are excluded; planned calendars are explicitly deferred. Defaults are screening approximations with citations, not ingested verified GADS microdata.
- Battery calendar/cycle degradation pack entries are deliberately blank/not modeled; finance nevertheless supports supplied degradation/replacements. A physical degradation library needs a validated model and chronology, not just a filled scalar.

## Inclusion and exclusion rules

A reusable library item is an independently described technology/class, dated official schedule/rule, model/performance curve, archetype, benchmark or time series with meaningful reuse. A measured customer file can be saved only in its authorized project/org scope. Public averages may seed labelled assumptions; they do not replace customer facts.

**Keep project/user-owned:** coordinates/topology/asset IDs; actual sizes/bounds/COD/age; fault level and connection offer; actual meter/CMMS/logs; chosen planning years; negotiated PPA/debt/offtake; current SOC/fuel/inventory; operator risk tolerance; entity eligibility. **Never library defaults:** API keys, credentials, permissions, approvals, artifact signatures, optimized capacities, calculated ENS/NPV/IRR/dispatch or “checked” verdicts.

**Europe and North America:** require explicit country/market/operator/technology tagging. Include UK/EEA/Switzerland where data supports it and US/Canada/Mexico separately. Do not transplant a US thermal fleet rate to an EU microgrid, Danish investment cost to a North American EPC quote, an EU voltage/frequency profile to a 60 Hz site, or a regulator auction strike to a corporate PPA quote.

**Every sourced value:** original and normalized value/unit, physical/financial basis, location/technology/size, publication/retrieval/effective date, source row/clause/URL, source bytes/hash where lawful, money year vs projection year, uncertainty/domain, verification state, redistribution rights, and transformation recipe. Publicly viewable does not mean openly licensed. Measured/assumed/illustrative/fitted/model-derived stay distinct.

## Inventory by card

Card IDs here are the proposed five-card vocabulary. Families can serve more than one card, but each input still has one canonical owner. Disabling a card must not silently remove a physical or price constraint used by another.
