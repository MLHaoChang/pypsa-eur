## Goal in plain words

Two small things are wrong in the coordinator's scripts.

1. **`premerge.sh` counts any line that looks like a verdict.** Its jq filter splits every comment into lines and counts a line starting with `GK OK @<sha>` or `UX NOT OK @<sha>`, from any comment by anyone. A session that pastes a reviewer's verdict into a report, or a comment that quotes one, counts as that reviewer's OK.
2. **`sessions.py` never flags ROTATE.** `list_sessions` reports `context_usage.used_tokens` as 0 or leaves it out, so the context column shows `-` or `0k`, and a session that is full is never flagged.

## Fix 1: which comments count as a verdict

What I checked on master (PRs #686, #688, #691, #692 comments):
- **Every comment is posted by the same GitHub user** (`MLHaoChang`): the gatekeeper, the UX reviewer and the PR sessions all use one token. So an author filter cannot tell a reviewer from a session.
- The footer is the same generic line on every comment (`_Generated by [Claude Code](https://claude.ai/code)_`). It names no session, so it cannot be a marker either.
- Real verdicts have the verdict as the **first line** of the comment, followed by the details and the footer.

So the smallest correct rule is a marker rule on the comment's shape:

- Only the **first non-empty line** of a comment is read. It must match `^(GK|UX) (NOT OK|OK) @([0-9a-f]{7,40})` (the same pattern as today, anchored to that first line). A verdict later in a comment, or one after a `>` quote mark, does not count.
- Because the author cannot separate the reviewers, a comment from a session that quotes or reports a verdict does not match, and that is the only protection. A session that deliberately starts a comment with `GK OK @…` is not stopped. Say this in the PR body and in a comment in the code. Do not claim the check authenticates the reviewer.
- Optional author filter, off by default: if `PREMERGE_REVIEWER_LOGINS` is set (space-separated GitHub logins), only comments by those logins count. It does nothing while every session shares a login; it is there for the day reviewers get their own accounts.
- A comment that has a verdict-looking line that the rule skips is reported (author, first 60 characters of the line), not silently dropped, so a reviewer who formats a verdict wrong sees it in the premerge output.
- The two review docs (line 5) gain one sentence: the verdict is the first line of the comment; the footer goes last.

Implementation:
- Move the parsing out of the jq one-liner into a new `scripts/coord/verdicts.py`. Reason: it can then be unit-tested without `gh` or git. Input on stdin: one JSON object per line, `{"login": …, "body": …}`. Output on stdout: `who<TAB>verdict<TAB>sha`, in comment order, exactly the shape the loop at l.327-353 reads today, so that loop does not change. Skipped lines go to stderr.
- In `premerge.sh`, l.323-326 becomes `gh api … --paginate --jq '.[] | {login: .user.login, body: .body}' | python3 "$(dirname "$0")/verdicts.py"`. Keep the `if verdicts=$(…)` and the "verdicts: not read" failure branch. The pipeline must still fail when `gh` fails: the script runs under `set -euo pipefail` (l.34), so a failing `gh` already fails the pipeline. Check that with a fake `gh` that exits 1, and say what you checked.
- The `python3` in `$PATH` is enough; the script uses the standard library only.

## Fix 2: `sessions.py` prints `?` for unknown context

- `context_tokens` returns `None` for a missing value **and for 0**: a session with a conversation has more than 0 tokens in context, so 0 means "not reported", not "empty".
- `fmt_context(None)` returns `?` (today `-`). A real number prints `<n>k`, with ` ROTATE` above `ROTATE_TOKENS` (200,000) as now. Only a real number can flag ROTATE.
- The docstring says: `list_sessions` does not report context reliably; `?` means unknown; the coordinator must read the real number with `get_session` (its `context_usage`) before deciding on a rotation, because this script only reads a saved file and cannot call tools. Fix the sentence that says fields a session lacks print as `-` so it says context prints `?`.
