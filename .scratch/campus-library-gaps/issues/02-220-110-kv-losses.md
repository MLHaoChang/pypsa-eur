# The 220/110 kV campus transformers' impedance and losses have no public source

Status: done (bound checked: NOT OK for all five units; replacement filed as issue 03)
Type: task
Blocked by: None

Filed by campus-library-gaps 01 (GK A, CL-01 plan GO, 2026-11-06).

## What was seen

The five 220/110 kV units in `gridspine/templates/data/campus_assets.yaml` (TR_220_110_125/160/200/250/315)
take their cost from cited Ei rows (R-NR-T-8-1..5; 125 and 160 MVA interpolated between them). Their `vkr_percent` (0.3), `pfe_kw` (1 kW per MVA) and
`i0_percent` (0.1) come from `producers/campus.py`'s class rule, tagged `assumed` with the note "no public
source; producers/campus.py class rule". `vk_percent` (12.5) is IEC 60076-5:2006 Table 1's minimum for
more than 100 MVA, not a typical value. No manufacturer datasheet with 220/110 kV losses was found.

## What to do

1. Read the EU Ecodesign Tier 2 minimum Peak Efficiency Index for liquid-immersed large power
   transformers (Commission Regulation (EU) No 548/2014, as amended by (EU) 2019/1783, Annex I) at 125-315
   MVA. EUR-Lex returned an empty 202 to the CL-01 session's container.
2. Check that each unit's class-rule losses meet that bound. PEI = 1 - 2(P0 + Pc0) / (Sr sqrt((P0 + Pc0) / Pk)),
   with P0 = `pfe_kw`, Pk from `vkr_percent` x Sr, and Pc0 = 0.
3. If a public datasheet or standard gives a split of no-load and load loss at these ratings, propose it
   as a reviewed change. A new value changes the library's sha256, so it needs a new defaults pack version.

## Done

The bound is checked and recorded here (pass, or a NOT OK naming the unit), and any sourced replacement
is merged or filed.

### 2026-11-11: Ecodesign bound checked, all five units NOT OK (campus-library-gaps 02, research session)

Owner chose "Research session checks it" (2026-11-11).

**Source.** Commission Regulation (EU) 2019/1783 of 1 October 2019 (OJ L 272, 25.10.2019), amending (EU) No 548/2014. Annex I, **Table I.7** "Minimum Peak Efficiency Index requirements for liquid immersed large power transformers", column Tier 2 (1.7.2021). Read from EUR-Lex (`https://eur-lex.europa.eu/eli/reg/2019/1783/oj`, HTTP 200; the earlier empty 202 did not recur). Table I.7 says PEI for ratings between rows is linearly interpolated.

| Rated power (MVA) | Tier 1 (1.7.2015) % | Tier 2 (1.7.2021) % |
| --- | --- | --- |
| 80 | 99,723 | 99,758 |
| 100 | 99,737 | 99,770 |
| 125 | 99,737 | 99,780 |
| 160 | 99,737 | 99,790 |
| >= 200 | 99,737 | 99,797 |

Tier 2 therefore reads 99.780 (125), 99.790 (160) and 99.797 (200, 250, 315 MVA).

**Computation.** PEI = 1 - 2(P0 + Pc0) / (Sr sqrt((P0 + Pc0) / Pk)), Pc0 = 0, P0 = `pfe_kw` (1 kW per MVA), Pk = `vkr_percent` 0.3 % x Sr.

| Unit | P0 kW | Pk kW | PEI % | Tier 2 % | Result | P0 that would pass at this Pk, kW |
| --- | --- | --- | --- | --- | --- | --- |
| TR_220_110_125 | 125 | 375 | 99.654 | 99.780 | NOT OK | <= 50.4 |
| TR_220_110_160 | 160 | 480 | 99.654 | 99.790 | NOT OK | <= 58.8 |
| TR_220_110_200 | 200 | 600 | 99.654 | 99.797 | NOT OK | <= 68.7 |
| TR_220_110_250 | 250 | 750 | 99.654 | 99.797 | NOT OK | <= 85.9 |
| TR_220_110_315 | 315 | 945 | 99.654 | 99.797 | NOT OK | <= 108.2 |

The class rule gives the same PEI (99.654 %) at every size, because P0/Pk and the loss-to-rating ratio are fixed. It misses Tier 2 by 0.126 to 0.143 points, and misses even Tier 1 (99.737). PEI bounds only sqrt(P0 x Pk). At the rule's uncited Pk of 0.3 %, P0 is 2.5 to 2.9 times what Tier 2 allows (125/50.4 = 2.5 at 125 MVA, 2.9 at 200 MVA and above), so the rule overstates losses against a compliant unit with that Pk; that is conservative for loss cost. A compliant unit with a higher Pk can lose more at high loading, so the rule bounds losses neither way. Note that the 0.3 % `vkr_percent` is itself uncited; the P0 limits above depend on it.

**Step 3: no sourced replacement.** No public datasheet or standard with a no-load/load-loss split at 125-315 MVA 220/110 kV was found in this session; Regulation 548/2014 sets only the PEI, not the split. Nothing is changed in `campus_assets.yaml`, so the library sha256 and defaults pack version stay as they are. Follow-up filed as issue 03.
