## Done and release criteria

A unit is done only when its code, all mapped positive/negative cases, migration/compatibility tests, ordinary approval/effect evidence, docs/release fragment and applicable remote checks pass. Each family link needs the exact test node/source/artifact, not a blanket checkbox. A failing required assertion must be fixed, never skipped/loosened to meet a count. Live language quality, independent domain review, real-use value and production approval are separate pending records.

Initial rollout uses existing opt-in profiles/readiness and current owning-package controls. Observe/propose paths can ship before an unsupported effect adapter; that adapter stays unavailable. Rollback stops new version-2 effects and preserves durable proofs/unresolved tasks; no deletion/downgrade or automatic rerun. No dollar-based budget service, answer cache or new task-profile API is required.
